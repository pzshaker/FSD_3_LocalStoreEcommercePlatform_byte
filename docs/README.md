# Project documentation

This folder records the agreed product decisions and the current technical direction for the artisan bakery ordering app.

## Read in this order

1. [Product requirements](product-requirements.md) — agreed customer and owner behavior.
2. [Screens](screens.md) — complete customer and owner screen inventory, behavior, and states.
3. [Technical architecture](technical-architecture.md) — selected stack and data-flow decisions.
4. [Backend API draft](backend-api.md) — proposed routes and backend rules.
5. [Five-phase roadmap](implementation-plan.md) — implementation checklist, working outcomes, and launch steps; backend first, desktop first.
6. [Selected visual direction](../design-variations/DESIGN.md) — Stitch Direction 2, Contemporary Neighborhood Market.
7. [Motion spec](../ANIMATIONS.md) — component-level motion, accessibility, and performance rules.

## Decision status

Product decisions in the requirements document were chosen during planning. The stack and backend-first approach were also selected. API route names, MongoDB document shapes, and implementation details are design proposals that can be revised before coding.

The visual direction is selected: Stitch Direction 2, Contemporary Neighborhood Market. The bakery brand, address, currency, verified product catalog, and other open policy details remain undecided; see [screens](screens.md).
